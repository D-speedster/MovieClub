فاز 0 — پیش‌نیاز: محیط را آماده کن (نیم روز)
================================================================

قبل از هر چیز مطمئن شو که پروژه اصلاً اجرا می‌شود:

1. فایل Backend/.env را بررسی کن — باید شامل موارد زیر باشد:
   - PORT=3001
   - MONGO_URI=آدرس دیتابیس MongoDB
   - JWT_SECRET=یک رشته تصادفی
   - SESSION_SECRET=یک رشته تصادفی
   - CORS_ORIGIN=http://localhost:3000

2. فایل Frontend/.env را بررسی کن — باید شامل موارد زیر باشد:
   - REACT_APP_API_BASE_URL=http://localhost:3001

3. دستور npm install را هم در Backend و هم در Frontend اجرا کن.

4. Backend را با "node Server.js" یا "nodemon Server.js" اجرا کن.

5. Frontend را با "npm start" اجرا کن.

6. مطمئن شو صفحه اصلی لود می‌شود و خطای console ندارد.

اگر این مرحله کار نکرد، بقیه فازها بی‌معنی هستند.

فاز 1 — امنیت Backend (اولویت بحرانی) — 1 روز
================================================================

این فاز مهم‌ترین فاز است. بدون آن پروژه از نظر فنی "ناقص" است.

مشکل فعلی:
- هر کسی (بدون login) می‌تواند فیلم اضافه، ویرایش یا حذف کند.
- این یک نقص امنیتی اساسی است که استاد حتماً می‌پرسد.

کارهایی که باید انجام شود:

1.1 — middleware احراز هویت را به route های زیر اضافه کن:
    - POST /content/new-content  (افزودن محتوا)
    - PUT /content/:id           (ویرایش محتوا)
    - DELETE /content/:id        (حذف محتوا)
    - POST /content/featured     (ست کردن پیشنهادی‌ها)
    - POST /settings/:key        (تغییر تنظیمات)
    - POST /settings/:key/upload (آپلود تصویر)
    - POST /trailers              (افزودن تریلر)
    - DELETE /trailers/:id        (حذف تریلر)

1.2 — مشکل Token را حل کن:
    - فعلاً isAuth از cookie می‌خواند ولی Login احتمالاً در localStorage ذخیره می‌کند.
    - یا همه جا cookie استفاده کن، یا همه جا Authorization header.
    - توصیه: در Login، token را در cookie httpOnly ذخیره کن (امن‌تر).
    - در فرانت‌اند، مطمئن شو axios با credentials: true ارسال می‌کند.

1.3 — ProtectedRoute فرانت‌اند را تست کن:
    - بدون login نباید بتوان به /admin رفت.
    - بعد از logout باید token پاک شود.

فاز 2 — مدل DownloadLink و صفحه جزئیات (اولویت بالا) — 1 روز
================================================================

این فاز "قلب" یک سایت دانلود فیلم است. بدون آن پروژه ناقص به نظر می‌رسد.

2.1 — مدل DownloadLink در Backend بساز با فیلدهای:
    - contentId (رابطه به Content)
    - quality (مثلاً: 480p, 720p, 1080p, 4K)
    - size (حجم فایل — رشته مثل "1.2 GB")
    - url (لینک دانلود)
    - encoder (مثلاً: x264, x265)
    - subtitle (آیا زیرنویس دارد؟ — boolean)
    - subtitleUrl (لینک زیرنویس — اختیاری)

2.2 — Route های Backend برای DownloadLink:
    - GET /downloads/:contentId  (دریافت لینک‌های یک فیلم)
    - POST /downloads            (افزودن لینک — فقط ادمین)
    - DELETE /downloads/:id      (حذف لینک — فقط ادمین)

2.3 — در پنل ادمین، بخش "مدیریت لینک‌های دانلود" اضافه کن:
    - انتخاب فیلم/سریال
    - افزودن لینک با کیفیت و حجم
    - لیست لینک‌های موجود با دکمه حذف

2.4 — در صفحه جزئیات فیلم (MoviePage)، لینک‌های دانلود را نمایش بده:
    - جدول یا کارت برای هر کیفیت
    - نمایش حجم، کیفیت، دکمه دانلود

فاز 3 — جستجو (اولویت متوسط) — نیم روز
================================================================

فعلاً SearchOverlay در هدر وجود دارد ولی به هیچ API وصل نیست.

3.1 — Backend: یک endpoint جستجو اضافه کن:
    - GET /content/search?q=کلمه
    - جستجو در فیلدهای title و description
    - از MongoDB text index یا regex استفاده کن
    - حداکثر 20 نتیجه برگردان

3.2 — Frontend: SearchOverlay را به این endpoint وصل کن:
    - با تایپ کاربر (debounce 400ms) درخواست بزن
    - نتایج را به صورت لیست نمایش بده
    - هر نتیجه به صفحه جزئیات لینک داشته باشد
    - حالت "نتیجه‌ای یافت نشد" را نمایش بده

فاز 4 — صفحات ناقص در Navigation (اولویت متوسط) — 1 روز
================================================================

در منوی هدر لینک‌هایی هستند که صفحه ندارند. این در دفاع بد به نظر می‌رسد.

4.1 — صفحه دسته‌بندی‌ها (/categories):
    - لیست تمام ژانرها (اکشن، درام، کمدی و...)
    - کلیک روی هر ژانر → لیست فیلم‌های آن ژانر
    - می‌توانی از همان صفحه Movies با فیلتر از پیش‌تنظیم استفاده کنی

4.2 — صفحه انیمه (/anime):
    - همان صفحه Movies ولی با فیلتر genre=انیمه از پیش اعمال‌شده
    - یا یک صفحه ساده با hero و grid فیلم‌های انیمه

4.3 — صفحات ساده (فقط برای اینکه 404 ندهند):
    - /about  → صفحه "درباره ما" با متن ساده
    - /contact → فرم تماس ساده (حتی بدون backend)
    - /news   → صفحه "اخبار" با پیام "به زودی"

4.4 — پنل کاربری (/User):
    - فعلاً فقط یک div است
    - حداقل: نمایش نام و ایمیل کاربر لاگین‌شده
    - دکمه خروج از حساب

نکات مهم برای دفاع
================================================================

1. حتماً قبل از دفاع، پروژه را یک بار از صفر (npm install + run)
   روی یک سیستم دیگر تست کن.

2. یک فلوی کامل آماده کن که بتوانی نشان دهی:
   ثبت‌نام → ورود → جستجوی فیلم → مشاهده جزئیات → دانلود
   ورود ادمین → افزودن فیلم → مدیریت محتوا

3. اگر وقت کم داری، فاز 2 (لینک دانلود) را حتماً انجام بده.
   یک سایت دانلود فیلم بدون لینک دانلود قابل دفاع نیست.

4. داده‌های تست واقعی داشته باش — دیتابیس خالی در دفاع بد است.
